# 로컬 문서 검증 화면

## 추출한 자료끼리 대조

화면 상단의 **1. 대조할 문서 선택**에서 유형별 실제 파일을 선택합니다. 선택을 바꾸고 아직 불러오지 않은 경우에는 확인·대조를 막아 이전 문서로 잘못 실행되지 않게 합니다.
**선택 자료 불러오기**는 대조 입력을 채운 뒤 **2. 대조할 값 확인**으로 이동합니다. 기간·금액·입금 거래를 확인하고 **입력값 확인** → **자료 대조**를 실행합니다. 불러오기 자체는 계산을 시작하지 않습니다.
근무기록·입금기록만 연결한 경우에는 예상 급여 자동 산정이 지원되지 않으며, 입금액 비교에 급여명세서나 확인한 실수령액이 필요하다고 안내합니다.
추출 상태·재실행은 추출 영역에 표시합니다. 자료 연결 전에 끝난 작업은 새로고침해도 현재 대조 작업으로 복원하지 않습니다.
**대조 결과** 탭은 상태별 건수, 항목별 대조표, 각 값의 실제 파일명, 방향을 설명한 차이, 원문 상세 창을 제공합니다.
상태 요약이나 필터로 차이 항목만 볼 수 있고 **결과 범위**에서 계약/명세서, 근무/명세서, 명세서 내부, 명세서/입금 비교를 나눠 봅니다.
**결과 기록**에서 이전 실행을 선택하면 당시 기간·입력·원문을 고정해 표시합니다. 이전 결과를 보는 동안 최신 결과의 설명·보고서 생성은 비활성화합니다.
과거 결과에 당시 자료 정보가 저장되지 않은 경우에는 현재 선택한 문서를 과거 근거로 표시하지 않습니다.

1. 각 PDF를 알맞은 유형으로 업로드하고 추출합니다. 기존 급여명세서와 Python OCR 명세서 모두 연결할 수 있습니다.
2. 상단 **대조할 문서 선택**에서 계약서·명세서는 한 건씩, 근무기록·입금기록은 필요한 자료를 선택하고 **선택 자료 불러오기**를 누릅니다. 문서가 없어도 가능한 비교는 독립 실행합니다.
3. 급여 기간, 단가 단위, 실근로/유급 시간 기준과 요약값을 확인합니다. 지급·공제 각 행의 금액을 수정할 수 있으며, 음수 환급·조정도 원문 그대로 비교합니다. 세부 항목을 모두 확인한 경우에만 완전성 체크를 선택합니다.
4. 은행 거래 중 해당 급여의 입금만 선택합니다. 원문 입금액이 잘못 인식됐다면 **원문 대조한 입금액**을 먼저 수정하고 이번 기간의 배분액을 입력합니다. 분할 입금과 다음 달 입금도 선택할 수 있습니다. 출금과 잔액은 입금으로 합산하지 않습니다.
5. 날짜·금액이 같은 중복 후보를 여러 건 포함하려면 각각 별개 거래인지 확인합니다. 명시된 계좌·거래번호가 같은 거래는 원문 근거를 모아 한 거래로 처리합니다. 동일 거래의 다른 사례 배분액과 합쳐 원금을 초과하면 확인이 거절됩니다.
6. **입력값 확인 · 계산에 반영** → **자료 대조**를 누릅니다. 대조 자체는 Python으로 실행되며 모델 호출·토큰 사용이 없습니다. 결과마다 양쪽 값·차이·급여 기간·각 원본의 근거를 볼 수 있습니다.

R-01 계약/명세서 단가, R-02 근무/명세서 시간, R-03 지급 세부합/총지급액, R-04 공제 세부합/공제 합계,
R-05 총지급액에서 공제를 뺀 금액/실수령액, R-06 실수령액/선택 입금 배분 합계를 비교합니다.
기간·단위가 다르거나 값·범위가 확인되지 않으면 차액을 확정하지 않습니다. 누락을 0으로 바꾸거나 전체 미지급액으로 단정하지 않습니다.
여러 근무기록의 요약 시간을 자동 합산하지 않으며, 사용자가 확인한 총시간도 각 명시기간이 겹치지 않고 대상 기간을 정확히 덮는 경우에만 비교합니다.
출퇴근 시각에서 실근로시간을 계산하거나 법정 임금을 새로 산정하는 기능을 이번 자료 연결 기능에 포함한 것으로 표시하지 않습니다.

연결할 때 추출 버전과 원문 근거를 고정합니다. 원본 유형 변경·재추출 시 연결 결과는 갱신 필요로 바뀌고 다시 불러오기·확인·대조해야 합니다.
진행 중 입력이 바뀌면 이전 결과를 최신 결과로 적용하지 않습니다. 연결·확인 행·입금 배분·결과는 새로고침 후 복구됩니다.
선택 자료를 모두 비우고 불러오면 연결이 해제되고 확인 입력은 초기화됩니다.

로컬 API: `GET /api/comparison-sources`, `PUT /api/cases/{id}/materials`.
선택 본문은 `contract_case_id`, `attendance_case_ids`, `payslip_case_id`, `deposit_case_ids`입니다.
확인 초안의 `material_review`에는 지급/공제 행 금액, 거래별 선택·확인 원금·배분액, 중복 후보 별개 거래 확인값이 저장됩니다.
연결 원문은 분석 스냅샷의 `authorized_sources`와 `evidence_catalog`에 포함되며 원본 포함 ZIP에도 반영됩니다.

## 급여명세서 · Python OCR

업로드 또는 문서 유형 선택에서 `급여명세서 · Python OCR`을 선택하면 PDF 텍스트층 유무와 관계없이
300dpi 이미지로 렌더링하고 로컬 Tesseract 한국어·영어 OCR로 읽습니다. 이 추출은 모델 호출·토큰 사용이 없습니다.
화면의 `Python OCR 전체 원문`에서 페이지별 인식문을 볼 수 있습니다.
Python 규칙은 명시된 총지급액·공제 합계·실수령액·지급일·전체 날짜 기간 및 지급/공제 항목의 이름과 금액을 추출합니다.
누락 합계를 계산하거나 단가·시간을 역산하지 않습니다. 여러 숫자 열·산식의 금액이 불명확하면 자동 채우지 않습니다.
알 수 없는 양식은 전체 원문을 남기고 수동 입력을 안내합니다. 낮은 인식 신뢰도·상충 값은 정규화 값을 비웁니다.
`ocr_unverified`는 OCR 인식문 기반이며 원본 PDF의 문자 인식 정확도를 검증했다는 뜻이 아닙니다.
원본과 직접 대조한 뒤 확인하세요. OCR 설치/실행 오류는 `OCR_UNAVAILABLE`/`OCR_FAILED`로 구분합니다.

Windows 로컬 OCR 설치는 [OCR 런타임 안내](OCR.md)를 참고하세요. 실행 파일과 언어 데이터는 저장소에 포함하지 않습니다.
공개 입력 유형에 `payslip_ocr`, 결과에 기본값이 빈 배열인 `recognized_pages`, 근거 검증 방식에 `ocr_unverified`가 추가됐습니다.
백엔드 연동에서 해당 열거형과 선택 필드를 허용해야 합니다.

프로젝트 루트에서 실행합니다. Python 3.14 로컬 가상환경을 사용하며 프런트 빌드는 필요하지 않습니다.

```powershell
uv sync --cache-dir .cache/uv
.venv/Scripts/python.exe -m agent.dev.test_server --port 4190
```

브라우저에서 http://127.0.0.1:4190 을 엽니다. 키와 두 모델 설정은 서버가 `agent/.env`에서 읽습니다. `--fixture` 옵션은 실제 호출을 하지 않는 가상 모드이며 화면 상단에 표시됩니다.

PDF 미리보기에는 Poppler의 `pdftoppm`이 필요합니다. PATH와 이 컴퓨터의 Codex 번들 경로에서 찾습니다. 다른 환경에서는 `AGENT_PDFTOPPM_PATH`에 실행 파일의 절대 경로를 지정하세요. 렌더러가 없으면 원본 PDF 다운로드는 계속 사용할 수 있습니다. 한글 PDF 생성은 `AGENT_FONT_PATH` 또는 Windows 맑은 고딕을 사용합니다.

## 화면 사용

1. **업로드할 문서 유형**에서 근로계약서·근무기록·급여명세서·입금기록을 선택하고 PDF를 업로드합니다. 이미 업로드한 파일도 오른쪽 **문서 유형**에서 변경한 뒤 해당 유형의 **추출하기**를 누를 수 있습니다. 유형 변경은 원본 파일을 유지하고 기존 추출값·입력 확인을 초기화하며 과거 작업의 유형은 바꾸지 않습니다. 작업 실행 중에는 유형을 바꿀 수 없습니다. 계약서의 저장된 평가 결과는 추가 호출 없이 불러오며, 다른 유형으로 선택한 문서에 계약서 평가 결과를 적용하지 않습니다.
2. 원문 근거를 누르면 해당 페이지 이미지와 인용문을 보여줍니다. 이미지 판독은 독립 OCR 검증을 하지 않으므로 직접 대조하세요.
3. 수정할 값을 입력하고 급여 대조 기간을 지정합니다. 근태·명세서·입금 입력은 선택이며 초기값은 미확인입니다. 단가 단위, 실제/유급 시간 기준, 지급·공제 항목 완전성, 입금 연결 범위를 직접 확인합니다. 0은 누락과 다릅니다.
4. 가상 작성본 3건에서만 **가상 보조자료 연결**을 선택할 수 있습니다. 시급 예제는 단가 차이, 월급 예제는 입금 차이, 누락 예제는 정보 부족을 보여줍니다. 일반 업로드에는 자동 연결하지 않습니다.
5. **입력값 확인** 후 자료 대조 → 설명 생성 → 보고서를 실행합니다. 원본 포함을 선택하면 ZIP에 원본 PDF와 해시 목록을 넣습니다.
6. 값을 바꾸면 기존 결과가 갱신 필요 상태가 되고 확인·재대조 전 설명·다운로드를 차단합니다. 새로고침하면 작업·확인값을 복구합니다. 중단 작업은 같은 ID로 이어서 실행하여 예산을 유지합니다.

근무기록은 날짜별 출퇴근·휴게 구간·명시된 근로시간, 급여명세서는 지급·공제 상세 항목, 입금기록은 거래별 입금·출금·잔액을 구분해 표시합니다. 각 값의 근거에서 PDF 위치와 원문을 확인할 수 있습니다. 명시된 요약값만 수기 확인 입력의 초안에 채우며, 상세 행의 합산·휴게 구간의 시간 환산·급여 거래 연결·입력 확정을 자동으로 수행하지 않습니다. 날짜별 근무일의 연도가 생략돼 있으면 원문 날짜 표시를 유지합니다.

실제 모델의 상세 표 응답은 행별 인용과 값 배열로 받아 긴 월간 표에서 동일한 키·인용의 반복을 줄인 뒤, 기존 공개 `ExtractionCandidate.fields`의 `work_1_date`, `earning_1_amount`, `transaction_1_deposit_amount` 같은 필드로 펼칩니다. 행 순서·동일 금액 거래를 유지하고 헤더·행 인용·배열 크기·단위를 검증합니다. 근무표의 `기록 단위: 시간(h)`처럼 명시된 단위 근거를 함께 검증하며 출퇴근 시각에서 실근로시간을 추정하지 않습니다.

머리글의 여러 줄 사이에 원문 제목이 끼어 있으면 각 줄을 원문 순서대로 대조하고 중간 제목을 포함한 실제 원문 구간을 근거로 보존합니다. 모델이 셀의 숫자 `8`에 머리글 단위를 붙여 `8시간(h)`로 반환한 경우, 해당 행에 숫자가 실제로 있고 머리글 단위로 검산한 결과가 모델의 정규화 값과 일치할 때만 원문 숫자 표기로 복구합니다. 존재하지 않는 숫자·머리글·단위 충돌은 계속 거절합니다. 이 보정은 `SOURCE_UNIT_FROM_HEADER` 등의 기록으로 남기며 일반 확인 이슈와 구분해 표시합니다.

빈 계약기간을 분석 기간으로 자동 간주하지 않습니다. 계약 시작일·종료일이 있으면 그 범위를 사용하고, 없으면 적용 여부를 별도로 확인해야 합니다. 연봉·일급을 월급·시급으로 환산하지 않습니다. 계약서의 출퇴근 시각을 실근로시간으로 계산하지 않습니다.

추출 검증은 인용문에 명시된 단위를 함께 확인합니다. 모델이 `8 hours`에서 원본 숫자 `8`만 반환해도 인용문에 시간 단위가 명확하면 `480`분으로 검증하며, 단위가 없거나 서로 다르면 추정하지 않습니다. `월 통상임금: 월 3,000,000원`의 `월`도 금액 문맥을 확인한 뒤 월급제로 검증합니다. 형식 재시도에는 실패 사유 코드와 허용된 필드 ID만 전달하며, 비공개 체크포인트의 `__model_validation__`에 보존합니다. 원문이나 예외 전문은 해당 진단 기록에 저장하지 않습니다.

모델이 `월 3,000,000원`, `1일 8시간`, `1주 40시간`처럼 기간 표시를 원본 값에 포함해도, 금액 단위와 필드의 일/주 기준이 일치하면 표시된 양을 검증합니다. 기간 환산이나 출퇴근 시각으로부터의 근로시간 계산은 하지 않습니다.

파싱을 마친 모델 응답은 비공개 체크포인트의 `__pending_model_outputs__`에 보존하며 단계 완료 후 제거합니다. 코드 수정 후 같은 작업을 이어서 실행하면 저장된 응답을 먼저 검증하므로, 검증을 통과한 응답은 모델을 다시 호출하거나 기존 호출 예산을 초기화하지 않고 복구할 수 있습니다. 응답을 보존하지 않았던 예전 실패 작업은 새 작업으로 추출해야 합니다. 과거 평가의 저장된 실패를 다시 읽는 경우에는 **저장된 실제 평가 결과 사용**을 해제해야 실제 추출을 실행합니다.

개발 중 실제 호출을 1회로 제한하거나 저장된 응답만 재검증하려면 서버를 먼저 중지한 뒤 실행합니다. 로컬 저장소는 단일 프로세스 전용입니다.

```powershell
# 최대 1회의 실제 모델 호출
.venv/Scripts/python.exe -m agent.dev.recheck_extraction --case-id <case-id>
# 추가 모델 호출을 차단한 재검증
.venv/Scripts/python.exe -m agent.dev.recheck_extraction --job-id <job-id>
```

자료 준비와 주석 명령은 API를 호출하지 않습니다. 실제 평가·설명 명령은 `gpt-6-luna`를 호출합니다. 완료·실패 결과가 이미 있으면 그대로 복구합니다. 실패한 자료를 새 작업으로 만들어 예산을 초기화하지 않습니다. 단계당 최대 3회이며 형식 재시도는 1회입니다. 모델 접근 실패 시 다른 모델로 전환하지 않습니다. 호출을 취소했을 때 이미 시작된 요청의 사용량은 미확정일 수 있습니다.

## 로컬 API

변경 요청은 JSON 본문과 `X-Local-Agent: 1` 헤더를 사용합니다. 업로드는 `application/pdf` 본문입니다. 반환되는 ID만 사용하며 경로나 실행 토큰을 전달하지 않습니다.

| 메서드 · 경로 | 기능 |
|---|---|
| `GET /api/health` | 모드·모델·연결 상태 |
| `GET /api/documents` | 자료 목록·평가 상태 |
| `GET /api/documents/{id}/pdf` | 원본 PDF |
| `GET /api/documents/{id}/pages/{page}.png` | PDF 페이지 렌더 |
| `GET /api/documents/{id}/auxiliary` | 3종 가상 보조자료 |
| `POST /api/uploads` | PDF 업로드·케이스 생성 |
| `POST /api/uploads?document_type=attendance` | 선택한 유형으로 업로드. contract/attendance/payslip/deposit 지원. 파일명은 선택적 X-Document-Name 헤더에 URL 인코딩한 표시 이름으로 전달 |
| `GET /api/extraction-profiles` | 유형별 요약·표 상세 항목 정의 |
| `POST /api/cases` | `{ "document_id": "filled-hourly" }` |
| `PUT /api/cases/{id}/document-type` | `{ "document_type": "deposit" }`. 기존 파일의 추출 유형 변경 |
| `GET /api/cases/{id}` | 초안·확인값·결과 복구 |
| `PUT /api/cases/{id}/draft` | 초안 저장·이전 결과 갱신 필요 표시 |
| `POST /api/cases/{id}/confirm` | 초안을 계산 입력으로 확정 |
| `POST /api/cases/{id}/jobs` | `{ "stage": "extract", "use_saved": true }` 또는 analyze/explain/report |
| `GET /api/jobs/{id}` | 상태·진행·실패·누적 사용량 |
| `POST /api/jobs/{id}/cancel` · `/resume` | 취소·같은 예산으로 복구 |
| `GET /api/artifacts/{id}` | 최신 확인 결과의 PDF·ZIP 다운로드 |
| `GET /api/evaluation` | 정답과 모델 비교 |

작업 생성은 HTTP 202와 작업 ID를 즉시 반환합니다. HTTP 서버와 asyncio 실행 루프를 분리했고 모델 작업은 최대 2개가 실행됩니다. 잘못된 Host·외부 Origin·변경 요청 헤더를 검사하며 임의 파일 경로는 제공하지 않습니다. 단일 사용자 로컬 개발 도구이므로 운영 인증·DB·다중 프로세스 작업 큐의 구현을 대체하지 않습니다.
